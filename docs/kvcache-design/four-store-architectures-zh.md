# 四个场景的 Store 架构草案

Prefill 跨实例共享已发布的对象。Decode 由请求所属 Client 管历史块映射。训练由 rank 所属 Client 管激活句柄。Engram 由加载器发布只读权重，推理 Client 按绑定版本取行。这四个所有权选择分别决定了谁能分配空间、谁能发布可读状态，以及读路径是否需要访问独立元数据服务。[原始需求与源码依据](./prefill-kvcache-store-requirements-zh.md) · [领域术语](../../GLOSSARY.md)

## 组件与完成条件

**Client** 接受业务读写请求，解析逻辑标识并提交传输。**Server** 提供存储容量、授权访问区间并负责安全回收。**Transport** 在已指定的源和目的区间间传输数据并报告完成。**空间管理**决定哪些物理区间可分配，**元数据管理**记录逻辑标识对应的位置和状态。**Master** 指独立部署的元数据服务。下列部署都是设计提案。

| 维度 | Prefill | Decode DSA | 训练 OpReplay | Engram |
| --- | --- | --- | --- | --- |
| Client 执行位置（稳态） | 计算节点 Host CPU | 计算节点 NPU | 计算节点 Host CPU | 计算节点 NPU |
| Server 部署位置 | 远端内存节点、远端 SSD 节点 | 远端内存节点 | 远端内存节点 | 远端内存节点 |
| 空间管理职责归属 | Master 选层级和节点，Server 分配对象区间 | Server 授段，Client 按请求分配块 | Server 授段，Client 按张量载荷分配变长区间 | Server 按表分片分配连续区间 |
| 元数据管理职责归属 | 独立 Master 持有共享 key 目录，Client 持有读写会话 | Client 持有请求块表和可读历史边界；DSA 自管热槽驻留表 | Client 持有 rank 私有句柄表；OpReplay 自管算子调用记录 | 加载器发布版本目录，Client 持有绑定版本的表描述符 |
| 稳态查询所需元数据的驻留位置 | 目录在 Master 的 Host DDR，会话在 Client 的 Host DDR | 请求块表、各层布局和可读历史边界在 HBM | 句柄表在计算节点 Host DDR | 表描述符在 HBM |
| Transport 提交位置 | 计算节点 Host CPU；读盘由 SSD 节点 CPU 提交 | 计算节点 NPU | 计算节点 Host CPU | 计算节点 NPU |

远端 DDR 的 Transport 端点在计算节点与内存节点。Server 在控制面注册内存、授权访问；授权有效时，网卡可直接处理数据访问。**提交位置、源地址、目的地址是三个独立属性**。训练由 Host 提交也可以走 RH2D。Decode、Engram 要求设备侧提交并观察完成，这属于待验证的硬件前提。

一次写入有两个可观察时点：Transport 读完源区间后，调用方可在其他使用者也结束后覆盖源；Store 满足相应场景的发布条件后，读者才可依赖远端副本。一次读取也有两个时点：目标 HBM 可见后可以开始消费；最后一个消费者结束后才能覆盖该目标。实现可以用同一事件满足多个条件，但接口要说明它保证哪些条件。

## Prefill

| 维度 | 设计 |
| --- | --- |
| 业务边界 | vLLM 管请求的本地 KV 块并指定 HBM 区间。Store 管前缀块对象的存放、发布和读取。 |
| 访问标识 | 读写均按前缀块 key。block-wise 指定整对象；layer-wise 另给对象内 range。同一 token 块的兼容层沿用同一 key。 |
| 空间分配 | 首次预留对象时，Master 选层级和节点，Server 按对象总长分配空间。逐层写入沿用这次预留。 |
| 读时寻址 | Master 按 key 查已发布对象的位置。Client 在读会话中固定该位置，再按层和分量加对象内偏移。 |
| 调用机制 | Worker 在进程内调用 Client。Client 用批量 RPC 向 Master 预留、发布和打开读会话。SSD 访问由 SSD Server 提交 NVMe 请求。 |
| 数据路径 | DDR 命中走远端 DDR → HBM；SSD 命中走 SSD → 注册 DDR 缓冲 → HBM。写入沿对应路径反向搬运。 |
| I/O 粒度 | 整对象覆盖约定各层。以 GLM‑5.3、BF16、128-token 块为例，单层 CKV 是一个 128 KiB 区间，KPE 是另一个 16 KiB 区间。 |
| 可读条件 | 其他实例可在所有约定层和分量写齐并提交后命中该对象。本次 get 的目标区间对 HBM 消费者可见后，对应层即可使用。 |
| 空间复用 | put 的 HBM 源在 Transport 读完且计算用完后可覆盖；get 的 HBM 目标在消费结束后可覆盖。远端区间等读会话及相关在途传输结束后可回收。 |
| 边界案例 | A 写完第一层，B 查询同一个 key。A 可以按完成依赖复用该层 HBM；B 只能命中已完整发布的副本。 |
| 时延指标 | 分 DDR 和 SSD 命中测量从开始查询 key 到首个所需层 HBM 就绪的 P99。后续各层分别记录 Attention 等待数据的时间。 |

## Decode DSA

| 维度 | 设计 |
| --- | --- |
| 业务边界 | DSA 决定 Top‑K、命中、逐出及 HBM 目标热槽。Store 接收源位置和目标区间，管理远端历史块并负责复制。 |
| 访问标识 | 写按请求、层和逻辑块号；读按请求、层和去重后的 miss token 位置列表，每个位置配一个 HBM 目标。 |
| 空间分配 | Server 提前授予远端 DDR 段。NPU Client 从段内为请求的逻辑块分配物理块号，同组各层共用映射。额度耗尽时等待补充或报告容量不足。 |
| 读时寻址 | NPU Client 校验可读历史边界，查请求块表得到物理块号，用当前层基址、块号和块内偏移计算各分量的远端地址。 |
| 调用机制 | 计算节点 Host 通过控制 RPC 申请段及访问凭据。稳态时 DSA 通过设备侧接口交付描述符，Client 在 NPU 上提交队列并观察完成。 |
| 数据路径 | 写出走 HBM 尾块 → 远端 DDR。召回走远端 DDR → DSA 指定的 HBM 热槽。 |
| I/O 粒度 | 写按单层完整块，例如 128 个 token。读按一个请求、一步、一层的 M 个实际 miss。打包行对应 M 个离散源地址，每址 656 B；512 B 与 64 B 紧邻且无额外字段时每址 576 B。两分量分存时则各有 M 个地址，分别每址 512 B 和 64 B。当前 BF16 分存示例为 M 个 CKV 地址各读 1024 B，另 M 个 KPE 地址各读 128 B。 |
| 可读条件 | 连续历史块的约定层和分量全部写入成功后，Client 推进可读历史边界。本层所需目标行全部在 HBM 可见后，Attention 可消费。 |
| 空间复用 | 尾块等写出读完源且计算用完后可覆盖。热槽由 DSA 在上一消费者用完后安排覆盖。请求结束后，Client 等在途读写结束再回收远端块。 |
| 边界案例 | DSA 更换热槽逐出策略，只要仍提供有效目标区间，Store 读接口就保持成立。M 为零时无需 RH2D。 |
| 时延指标 | 按 M 和行布局分组，测量从 DSA 交付当层 miss 列表到该批全部目标行在 HBM 可见的 P99。 |

## 训练 OpReplay

| 维度 | 设计 |
| --- | --- |
| 业务边界 | OpReplay 决定保存哪次算子输出、何时重放及消费。Client 维护激活副本，按给定消费次序和 HBM 预算安排搬运。 |
| 访问标识 | 登记时传入该次调用的张量并取得激活句柄。换出、预取和消费沿用这个句柄。 |
| 空间分配 | Server 向 rank 的 Client 授予远端段。实际换出时，Client 才按张量载荷长度从段内分配区间。 |
| 读时寻址 | Client 在 rank 私有句柄表中查驻留状态、布局和区间。有效 HBM 副本可直接使用；读取远端副本时由段和偏移确定源地址。 |
| 调用机制 | OpReplay 在 rank 进程内调用 Client。Client 以控制 RPC 取得远端段，由 Host 向 Transport 提交换出和预取请求。 |
| 数据路径 | 换出走 HBM → 远端 DDR；预取走远端 DDR → HBM。 |
| I/O 粒度 | 按一个 rank 的单个张量载荷双向搬运。例如一个连续 BF16 张量 `[1, 4096, 4096]`，换出或读回一次为一个 32 MiB 区间。 |
| 可读条件 | 登记返回后句柄有效。远端写成功后可依赖远端副本。重放可直接消费有效 HBM 副本，预取中的副本须等目标 HBM 就绪。 |
| 空间复用 | 作为最后有效副本的源 HBM，要等远端副本可恢复且源的在途访问结束后才可释放。预取目标在消费结束后可释放。句柄消费或取消后，远端区间等在途传输结束再归还。 |
| 边界案例 | 前向取得句柄后立即重放，可以命中仍在 HBM 的激活。若在预取中取消重放，句柄可作废，但远端源区间仍受在途读保护。 |
| 时延指标 | 按载荷大小分组，分别测量从发起换出到源 HBM 可释放的时间，以及重放算子其他依赖已满足后仍需等待激活的时间。 |

## Engram

| 维度 | 设计 |
| --- | --- |
| 业务边界 | 模型从 token 上下文计算哈希行号，维护 head 到输出位置的对应关系，并在使用 TP 时汇合各 rank 的结果。Store 提供指定版本的权重行。 |
| 访问标识 | 加载按模型版本、层及分片写入。推理按已绑定的版本、层和行号列表读取，调用方给出对应的 HBM 输出区间。 |
| 空间分配 | 加载时 Server 按表分片分配连续区间。推理阶段沿用该版本已分配的区间。 |
| 读时寻址 | Client 在绑定版本的描述符中按行号范围选分片，用分片基址加分片内行号乘行宽，得到远端源地址。 |
| 调用机制 | 加载器在计算节点 Host 通过 RPC 请求 Server 分配分片。实例绑定版本时取得描述符。推理时模型通过设备侧接口交付行号，NPU Client 批量提交读取。 |
| 数据路径 | 加载时将权重上传至远端 DDR。推理时各 rank 所需权重行从远端 DDR 读入本 rank 的 HBM 输出区间。 |
| I/O 粒度 | 加载按分片写。DS‑V4.1‑Flash 推理时，每个有效文本 token、每个 Engram 层对应 **24 个离散源地址，每址读 264 B**，按全部哈希 head 计。 |
| 可读条件 | 加载器在版本所需分片全部就绪后发布目录，推理实例随即可以绑定该版本。设备输出就绪且模型所需的 TP 汇合完成后，门控可以消费。 |
| 空间复用 | HBM 输出区间等最后一个模型消费者结束后可覆盖。旧版本的远端分片等旧绑定全部释放且在途读结束后可回收。 |
| 边界案例 | 一批权重行读取期间发布新版本。该批仍按同一绑定取齐旧版本的所有行，下一次显式绑定才可切换。 |
| 时延指标 | 行号确定后可提前提交。分层测量从门控其他依赖已就绪到本批行可消费的额外等待时间，已经就绪时记零。首个 Engram 层单列。 |

## 首个待定问题

**远端 Transport 能否在目标 NPU 上由设备提交整批离散 RH2D，并在同一设备上向消费算子报告目标 HBM 可见？** 这是 Decode、Engram 能否采用上述部署的共同前提。验证时，Decode 保留每层实际 miss 列表和等待窗口，Engram 保留每层 24 个离散地址及其可提前提交的时间。训练的大张量带宽测试无法回答这个问题。当前文档给出拟议架构及验证口径，远端时延尚待实测。
